# 231 — Nested groups dock layout

**Parent:** [221 — Collections & media (spec)](221-collections-media-spec.md)

**What to build:** The dock renders two-level groups correctly at its real content width. At 420 CSS px or wider, child sub-headers are indented and always expanded, and the parent chevron collapses the whole subtree. Below 420, the subtree flattens into one list with no child sub-headers. The same pass fixes the current narrow-width group overflow: labels truncate, count badges stay visible, and rows stay inside the strip.

**Blocked by:** 230 — Nested groups main-app UI.

**Status:** done — amended 2026-10-24 (children collapse, per-card colour); manual width/DPI/theme pass validated by the user 2026-10-26

- [x] The layout mode is driven by the tab panel's **content width** via a container query, not the window width or a new size constant.
- [x] At ≥ 420 CSS px: parent header, direct items, then each child sub-header indented and always expanded. The parent chevron collapses the entire subtree. ~~child groups have no chevron~~ Superseded 2026-10-24: the child sub-header now carries its own chevron and collapses independently — at that width the strip has room for it, and "always expanded" removed a control the parent level already had.
- [x] Below 420: one flattened list — parent header, then all items in tree order (parent direct first, then each child's items in child order), with no child sub-headers.
- [x] A parent with visible descendants but no direct items still renders; a parent whose whole subtree is hidden drops; a parent with no visible descendants drops.
- [x] Labels truncate, count badges stay visible, and no row overflows at 340 px content width. *(Layout supports it; the 340 px visual pass is still pending a human.)*
- [x] The dock has no group menus and no color editing; the read-only surface stays read-only.
- [x] Pure tests cover the mode decision at 419/420/421 CSS px and the flatten/nest ordering. Manual evidence covers 340/420/800 px, fixed/auto-hide/bezel, 100/150/200 % DPI, light/dark, and a parent with only child items. *(Pure tests green; the manual matrix is not yet verified — see notes.)*

**Claims (recheck at dispatch):** the dock page; the shared accordion's flush/nested presentation; a pure layout-mode function. **Explicitly not built:** a new dock window or size constant; changes to dock modes/width formulas; drag; group menus/color editing in the dock.

**Verification notes (2026-10-24):** `src/lib/dockGroupLayout.ts` owns the decision — `DOCK_GROUP_NEST_WIDTH = 420`, `dockGroupMode` (419 flat / 420 nested, pinned at 419/420/421), `dockGroupSections`, `dockSectionCount`, `flattenDockRows`. The runtime line is the tab panel's container query: `.qlw__list` is `container-type: inline-size` and `.qlw__groups` flips `--dock-group-mode` at `@container (min-width: 420px)`; the page's `ResizeObserver` reads that sentinel, so padding and the scrollbar sit outside the measured box and the window's own width never decides. `flattenDockRows` keeps tree order (parent direct first, then each child in child order). Nested mode renders the shared `GroupAccordion` (`flush nested`), 12 px indented (`--space-3`), so a child's beam clears the parent's instead of doubling it. **Amendment (user-reported, 2026-10-24):** two things changed after the first implementation. (1) *Per-card colour in flat mode* — flattening used to repaint every child row with the parent's tint, which erased the child's own identity; now each row passes its own group's colour through `dockGroupColor` into `QuickLaunchRow`, so a card keeps its hue while the single beam stays the parent's colour, and a neutral child explicitly clears the inherited tint (`dock-row--neutral`). The tint formula itself moved to one global `.group-tint` utility in `tokens.css`, shared by `GroupAccordion` and `QuickLaunchRow`. (2) *Collapsible children* — the child sub-header was static (`collapsible={false}`), so the nested view could not be minimized below the parent; each tab now passes its own collapse store (`launchCollapse` / `actionCollapse` / `clipCollapse`) and the dead `collapsible` prop plus `.group--static` variant were removed. Tests: `dockGroupLayout.test.ts` covers mode, flatten order, per-card colour, collapsible child wiring, the single tint formula, and the nested indent; `npm.cmd run test` 561 passed (44 files), `npm.cmd run check` 0 errors / 3 pre-existing warnings, `node tools/contrast-check.mjs` all pass (including every group hue on its tint and hover), `node tools/ownership-gate.mjs` pass. **Not yet verified by hand:** 340/420/800 px content widths, fixed/auto-hide/bezel modes, 100/150/200 % DPI, light/dark, and a parent that has only child items.

**Amendment (user-reported, 2026-10-24): the strip's gutter is not colour-dependent either.** The flush variant now reserves its 8 px leading gutter on every group, and the loose rows above the sections (`.qlw__groups > .qlw__entries` / `.qlw__actions` / `.qlw__clips`) take the same step, so turning a group's colour on or off — or nesting it under a coloured versus neutral parent — never shifts a row. Same regression test as ticket 230.
