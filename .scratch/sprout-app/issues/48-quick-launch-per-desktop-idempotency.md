# 48 — Quick Launch: per-desktop idempotency and reliable window placement

**What to build:** Quick Launch opens a fresh window for every app entry — placed on its assigned virtual desktop (or the current desktop) — and is truly idempotent: re-running it never duplicates or disturbs a window the user is actively using. Root cause (found live: Control Panel + Command Prompt unassigned; File Explorer + Microsoft Edge assigned to Desktop 2): the skip-already-running check matches full exe paths, so (a) Command Prompt is skipped whenever any cmd.exe runs anywhere on the machine, (b) Edge's versioned install path (`...\Application\151.0.4129.86\msedge.exe`) never matches the running instance's unversioned image, so a launch handed to the running Edge produces no new window on Desktop 2, and (c) after an Edge update the target path dies with a silent 15 s stall. The image-match window fallback also grabs the first visible window of the app's image — an old Explorer folder gets yanked to Desktop 2 while the new window stays on the current desktop.

**Blocked by:** None — can start immediately

**Status:** done — probe green twice, 231 unit tests, svelte-check clean, synced to the share

- [x] The skip rule is rescoped from "is the app's exe running anywhere" to "does the app already have a window on the target desktop": an assigned entry skips (no-op) only when a window for that app already exists on its desktop GUID; an unassigned entry skips only when a window exists on the current desktop; otherwise the entry launches a fresh window and places it on the target desktop — windows elsewhere are never skipped over or moved
- [x] Window matching is by image file name (basename), not full path — versioned install directories (Edge, Slack, Discord) skip and place correctly, and the skip decision comes from per-window desktop queries (which desktop is each window on), not from the process table
- [x] Handed-off launches (single-instance apps, Start-Menu shortcuts the shell reuses) place their NEW window: the engine snapshots the visible-window set before launch, and window resolution prefers a window that appeared after the launch — the running Edge's new window, the fresh Explorer window — never an old one
- [x] An entry whose target no longer exists on disk (an app updated its version folder) fails fast with "target no longer exists — update this entry" in the failed list — no silent 15 s stall
- [x] The run summary (system notification + page event) lists skipped entries with the reason ("Command Prompt — already open on this desktop"), so a no-op run is never silent
- [x] Live feedback-loop probe (integration test driving the real engine on this machine) proves three states: Edge running → fresh window placed on Desktop 2; Edge closed → fresh window placed on Desktop 2; Edge already on Desktop 2 → skipped, nothing disturbed.
