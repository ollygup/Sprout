# 119 — Dock reveal reads precomputed wall + no handle

**What to build:** The dock stops trying to guess "is this a middle line?" while checking the mouse. It reads the wall check [eligible edge / cursor-stop] that 111 already computed from the screen layout, and skips the whole open logic on a middle line [seam]. When hidden, the strip has no handle at all [off-screen] — the wall itself is the target. Implements **Studies B–E** from `docs/research/0011-natural-edge-reveal.md`.

**Amends:** 112 — layered auto-hide reveal gate (keeps 112's `done` history; follow-up that replaces sliver-hover with wall pressure).
**Blocked by:** 111 — must reuse 111's wall helper.
**Status:** done

- [x] When the current screen's edge is a middle line [ineligible — touches another screen by >1 px], the opener does nothing [short-circuit: reset gate, return false] and there is no handle to hit [hidden = off-screen, not 2 px sliver (Study B)]. A request to put the dock there is refused with the same line Settings shows: `Borders another display — cursor can't stop there`. Applies to both `left | right` on each screen — top screen left/right independent from bottom screen left/right [Studies A + B]
- [x] When the edge *is* a wall [eligible], opening needs all three together [Studies C + D]: (1) push must be more toward the wall than along it [direction gating — along > toward adds nothing]; (2) park on the wall a moment [dwell ~0.2 s]; (3) leaving the wall before the park finishes cancels [cancel-if-left]. A quick brush past the wall and snap-back to the close button [×] in ~30 ms — even a big slam — never opens (Study D cases 1–3). Once open, staying inside the strip keeps it up; leaving it hides again with a short grace [hide hysteresis]. Existing 112 cases stay green — `graze`, `fly-through`, `deliberate push` now exercise this wall + dwell, `cross-seam transit` asserts via wall check
- [x] Wall status is re-read when screens move/are added/removed [WM_DISPLAYCHANGE — same signal Settings listens to, sent from the dock window's message handler (AppBar callback)]; the opener resets and the next blink sees the new wall. No extra screen polling — only the usual mouse check every blink [polling ~16 ms] remains, now `if not a wall { do nothing }` [Study E — WebView2 eats mouse-move events]
- [x] Single wall source for identity (EDID) and wall check (no second screen list that could drift mid-call). Tests cover human cases layman-named: side-by-side same size → middle line off; side-by-side offset (only 30% touch) → whole middle still off; diagonal corner only [1 px] → outer wall stays; top/bottom stacked → left/right of top and bottom each independent; single screen → both outer walls on
- [x] No handle on any edge [no sliver across any]: hidden means no click box on left *or* right, so left-edge invisible-box artifact is gone (Study B). Visual design: hidden ↔ shown slides [ease-out ~0.18 s]; no persistent handle state
