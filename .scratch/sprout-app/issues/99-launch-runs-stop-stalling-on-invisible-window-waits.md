# 99 — Launch runs stop stalling on invisible window waits

**What to build:** A Launch row play / Start click can lock every start affordance and pin "Starting…" for up to 15 seconds after the app is visibly open. Root cause: every app-kind entry held the whole run open until its "new main window" appeared or `WINDOW_TIMEOUT` (15 s) expired — a wait that exists only to find the window a desktop move needs. For entries without a live desktop assignment nothing consumes that confirmation, yet the single-flight guard made the whole UI wait on it. Fix: only an entry that actually owes a desktop move holds its slot; commands and unassigned apps free at spawn, so a normal run completes the moment the last spawn lands.

**Blocked by:** None — follow-up to 94 (which surfaced the pre-existing stall by putting per-entry starts in reach).
