# ADR audit — 2026-09-05

All 29 numbered ADRs were read in full, including earlier amendments, and their material present-tense claims were compared with current executable source, configuration, and workflow definitions. Tickets and specifications were not used as evidence. Code comments were not treated as proof. **26 ADRs received dated amendments; 0002, 0015, and 0029 required no change to their current decisions.**

Original decision bodies and earlier amendments are preserved. Only top Status pointers were updated and new `## Amendment — 2026-09-05 (executable-source audit)` sections appended. The index was refreshed, including the obsolete seed-file warning. “Amended” includes factual precision corrections and documented implementation gaps; it does not mean 26 architectural decisions were reversed.

## Evidence and limits

The table records the inspected code locations; detailed findings belong to each ADR amendment. Relative code names in an evidence cell continue in the same source directory unless another path is given. Symbols are preferable to fragile line numbers when resuming after source changes.

This is a static source audit, not a fresh runtime certification. No application code changed, no Git commands ran, and no application test suite, installer, update, or live launch probe was executed. Historical release/parity events, prior review dates, private-key custody, current repository visibility, and deployed artifacts cannot be established from this source tree. Existing historical text is retained without presenting it as re-verified fact.

A difference between code and an accepted requirement remains an implementation gap unless an explicit decision changes the requirement. In particular, the amendments do not approve weaker install-version enforcement, stale Library requests, inaccurate outcomes, or duplicate Windows ownership. Future architecture work must establish the actual baseline and separate structural changes from behavioral fixes.
